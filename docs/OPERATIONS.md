# تشغيل VPS والصيانة

## التجهيز
1. احصل على VPS Linux تديره وعلى نطاق تحت سيطرتك. لا توجد بيانات وصول مقدمة في هذه الجلسة.
2. افحص الذاكرة والتخزين والنسخ الموجودة والمنافذ 80/443 قبل أي تغيير. نقطة بداية تقديرية 4GB RAM وقرص يناسب الصور والنسخ؛ ليست نتيجة قياس على VPS.
3. ثبّت Docker Engine وCompose من المصادر الرسمية. أنشئ مستخدم تشغيل محدودًا ومفتاح SSH وجدارًا يسمح فقط بالمطلوب. لا تغير خدمات أخرى.
4. انقل المصدر دون `.env` المحلي أو `data` أو بيانات العرض. انسخ `.env.example` إلى `.env` على الخادم واضبطه محليًا بصلاحية 600. استخدم كلمة PostgreSQL عشوائية طويلة من أحرف hex لتجنب أخطاء ترميز رابط الاتصال.
5. اضبط DOMAIN إلى نطاقك الحقيقي وPUBLIC_ORIGIN إلى HTTPS له. يُجبر Compose الإنتاج على PostgreSQL والكوكيز الآمنة والدفع المعطل. لا تعرض 5432 أو 8000 أو 3000 خارجيًا.

```sh
docker compose config --quiet
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=100 backend worker frontend proxy
```

خدمة migrate تشغل Alembic قبل API. شغّل تهيئة التصنيفات من `python -m app.bootstrap` عند تجهيز قاعدة فارغة. أنشئ المدير تفاعليًا داخل الحاوية ولا تعرّف مديرًا أو كلمة مرور افتراضية:

```sh
docker compose exec backend python scripts/create_admin.py
```

Caddy يطلب شهادة HTTPS عندما يشير DNS إلى الخادم وتكون المنافذ متاحة. وجود Caddyfile ليس إثبات إصدار شهادة؛ افحص سلسلة TLS وتاريخ الصلاحية بعد النشر. المصادقة الإضافية للمدير مطلوبة في الإنتاج؛ راجع إعدادها في دليل التكاملات. توثيق OpenAPI معطل خارجيًا في الإنتاج ويمكن تصدير المخطط محليًا.

## التشغيل والتحديث
- إيقاف دون حذف البيانات: `docker compose stop`؛ إعادة التشغيل: `docker compose start`.
- تحديث: أنشئ نسخة احتياطية وتحقق منها، سجّل الإصدار الحالي، اختبر الإصدار الجديد على قاعدة مستقلة، ثم ابنِ الحاويات وأعد تشغيلها. لا تستعمل `down -v`؛ يحذف البيانات.
- تحقق من `/api/health` ومن صفحة السوق وتسجيل الدخول والبحث بعد التحديث. اختبر رحلة على بيئة staging فقط حتى يتوفر مزود معتمد.
- العامل الخلفي مطلوب لتحرير حجز المخزون بعد انتهاء 20 دقيقة وإعادة إرسال إشعارات Telegram. يوجد claim/lease عشوائي لمدة دقيقتين ووقف بعد ثماني محاولات مع تنبيه داخلي. إعداد MVP يبقى عاملًا واحدًا؛ اختبر الحمل والإرسال المتزامن قبل زيادته.
- السجلات لا تطبع أجسام الرسائل ولا مفاتيح التكامل. فعّل حدود حجم وتدوير سجلات Docker ومراقبة مساحة القرص وإعادة التشغيل والنسخ الاحتياطية.

## نسخ واستعادة PostgreSQL
`sh scripts/backup.sh` ينشئ pg_dump بصيغة custom وأرشيف الوسائط والمستندات الخاصة وبصمات SHA-256 بصلاحيات مقيدة ويحتفظ 14 يومًا. خزّن نسخة مشفرة خارج VPS واضبط مهمة دورية وتنبيهًا على رمز خروج غير صفري. التنبيه الخارجي يحتاج قناة تشغيل لم تقدم في الجلسة.

اختبر الاستعادة إلى قاعدة **جديدة مستقلة** وvolume وسائط **جديد**، وليس فوق الإنتاج:

1. تحقق من SHA-256 للملفات والوقت والمساحة، ومن أن النسخة تخص هذا الإصدار.
2. أنشئ قاعدة جديدة باسم مراجعة تحدده صراحة عبر `createdb`، ثم استخدم `pg_restore --no-owner --no-privileges --exit-on-error` عليها دون `--clean`.
3. فك الوسائط والمستندات الخاصة في volume جديد مخصص للمراجعة، وتحقق من عدم وجود مسارات خارجة عن جذر الأرشيف قبل الاستخراج.
4. شغّل staging عليها، قارن أعداد السجلات والعلاقات وصورًا مختارة وأكمل شراء تجريبيًا.
5. لا تحول الإنتاج إلا بعد توثيق النتيجة ونافذة الصيانة والنسخة القابلة للرجوع. لا تحذف القاعدة القديمة ضمن إجراء الاستعادة.

`scripts/verify_local_backup.py` ينفذ اختبارًا غير مدمر لـSQLite والوسائط والمستندات الخاصة في مجلدين جديدين ويكتب `reports/backup-restore.json`. هذا لا يغني عن استعادة PostgreSQL الفعلية على بيئة النشر.

## إضافات الإصدار المحلي الثاني
اضبط MAIL_TRANSPORT=disabled أو smtp في الإنتاج؛ local مرفوض. اضبط PRIVATE_LINK_SECRET في بيئة التشغيل. النسخ تحتوي مستندات شخصية وروابط استعادة، لذا تقيد الصلاحيات وتشفّر النسخة الخارجية وتراجع مدد الاحتفاظ. جرب رابط وثيقة مؤقتًا بعد الاستعادة ولا تستعد مفتاحًا عشوائيًا مختلفًا على كل عامل.

اجتازت الترحيلات واختبارات التطبيق PostgreSQL 17.10 محليًا في مخططات معزولة؛ هذا لا يثبت تشغيل Docker أو VPS أو استعادة pg_dump. دليل الاختبار في reports/pytest-postgresql.xml وpostgresql-migrations.json. استعادة الإنتاج والحاويات وTLS ما زالت بوابات staging.

## استقرار الاتصال المحلي
مشغل الإنتاج المحلي يحمل frontend/scripts/local-http-agent.cjs لتعطيل إعادة استخدام اتصال HTTP في وكيل Next المحلي، ويضبط مشغل API مهلة keep-alive إلى130 ثانية؛ جرى التحقق من الخمول والتزامن في reports/proxy-stability.json. إعداد Caddy يرسل API مباشرة للخادم. لا تعدل ملفات التبعيات المثبتة لعلاج الاتصال. عميل الواجهة يعيد القراءة المؤقتة فقط، ولا يعيد طلبات الكتابة تلقائيًا. سجل بدء PostgreSQL الاختباري يوجه إلى ملف control.log لتجنب تعليق أنابيب بدء العملية؛ لا تطبع runtime.json لأنه يحتوي بيانات اتصال.

## النشر التجريبي على buyutna.wardat.xyz
منذ 2026-10-30 تعمل نسخة تجريبية على https://buyutna.wardat.xyz فوق سيرفر wardat.xyz المشترك، بوضع staging ودفع وتوصيل محاكيين. الإعداد في deploy/server: ملف Compose مستقل بلا Caddy، ومنفذان على loopback يخدمهما nginx الموجود، وشهادة certbot خاصة بالسب دومين. أوامر التشغيل والتحديث والنسخ والإزالة في deploy/server/README.md. ليس هذا نشرًا تجاريًا؛ بوابات الدفع والتوصيل والاعتمادات في تقرير القبول ما زالت قائمة.

## الدفع الحقيقي عبر Tap (منذ 2026-11-05)
السيرفر يعمل بـ`PAYMENT_PROVIDER=tap` ومعاملات حقيقية. قواعد التشغيل:

- كل دفعة تُفتح تُسجل في جدول `tap_charges` قبل توجيه الدافع إلى Tap. حالتها تتغير فقط بعد قراءة المعاملة من Tap نفسها، عبر صفحة العودة أو الـWebhook (`/api/payments/webhook/tap`) أو مسح العامل كل دقيقة للمعاملات التي مضى عليها 10 دقائق. لذا يجب أن يبقى العامل (`worker`) يعمل.
- المعاملة المكتملة التي لا تنطبق (طلب أُلغي أو انتهى، فاتورة مدفوعة مسبقًا، مبلغ أو عملة مختلفة) تصبح «تحتاج استردادًا» مع إشعار للإدارة وللدافع. عالجها من لوحة الإدارة ← «معاملات Tap»: «استرداد عبر Tap» يعيد المال فعليًا، و«عولجت خارج المنصة» إن استُردت من لوحة Tap.
- «فحص معاملة برقمها» في نفس التبويب يقرأ أي معاملة `chg_…` من Tap ويطبّقها؛ استخدمه للدفعات السابقة لهذا الإصلاح (مثل اشتراكات دُفعت ولم تتفعّل) بعد نسخها من لوحة Tap.
- استرداد طلب مدفوع (كامل أو جزئي) من صفحة الطلب للمدير يمر عبر Tap ويسجل في السجل المالي ويُشعر العميل.
- بعد أي نشر: افحص `/api/health` (يجب أن يظهر `"payments":"tap"`)، وافتح «معاملات Tap» ← «تحتاج استردادًا».

الترحيل `006_payments_chat` آمن على قاعدة السيرفر التي أُضيف فيها `households.pickup_enabled` و`order_chat_messages` يدويًا: ينشئهما فقط إن غابا. خذ نسخة احتياطية قبل `alembic upgrade head` كالمعتاد.
